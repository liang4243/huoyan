## 简短自然的询问方式

优先使用 `ask_shop_invoice`，一次完成真实客服入口、加载核验、店铺去重和短草稿；在已有用户授权下办理精确草稿授权后，以同一requestId续接发送并读回复。详见[多步工作流操作手册](多步工作流操作手册.md)。

店铺能力询问只问：“你好，你们家能开票吗？开票金额和实付金额一样吗？”不附学校用途、商品链接、SKU、数量或其他追问。单步接口可用 `prepare_invoice_inquiry(inquiryScope="shop", inquiryStyle="school_project")`，无需选齐SKU。店铺能开票不自动推导某个SKU最终价。

明确进行商品报价研究时仍用product范围，要求准确商品/SKU/数量；旧short话术保留兼容。历史已授权草稿和已发消息不改写，不为改文案多发消息。

## 已支持的页面与消息

目前实现网页语义聊天结构及实际观察到的淘宝网页旺旺适配：真实客服入口、会话标题、编辑框、发送按钮、文本气泡和富文本商品卡。支持已允许淘宝/天猫站点范围内iframe、新标签和嵌入面板；同标签跳转保留真实后退路径。只有已发现且能核验店铺/接收者对应关系的会话才能操作。真实验收覆盖本次旺旺模板的单次发信、本方文本/已读读取和对端商品卡接收，不能推及所有淘宝/天猫模板或尚未出现的回复形式。不支持原生旺旺/千牛、未核验外域、语音和附件内容识别。


真实编辑框是 `.ww_input .edit[contenteditable=true]`，消息里的 `.edit[contenteditable=false]` 不是输入框。已观察文本结构 `.message-item-line .message-item`、`.content .expression-parser pre.edit`、`.first-line .time` 和本方 `.self`；仅导出正文/时间/状态，不导出昵称头像。无稳定消息ID时用弱观察序列，未读/已读与送达分别记录。非self且有已观察到的对端布局和发送人行时可标incoming/会话对端；其它未知方向保留unknown。senderIdentityVerified仅表示可见作者文字与商家标题对应，不能认证具体真人或机器人身份。


商品卡真实结构为 `.content .im-template-msg.dx-msg-wrap`，可直接读取文字，不必OCR或截图。观察到的非self消息布局和发送人行可证明消息来自当前会话对端；客服个人身份/是否机器人仍未验证，不把昵称相似当成资质证明。买家与客服昵称、头像不导出。适配器由“未解析卡片”升级为文字时仅在唯一时间/图片观察匹配下保留证据ID，避免把同一张卡当成两条新消息。

真实店铺链接可能在交互时自动附加统计参数。复用对比保留源标签/源URL、唯一店铺身份、商品/SKU/报价和已观察店名，忽略店铺入口链接本身的统计地址差异；不导航该链接，也不以此放宽不同店铺或SKU变化的检查。

客服入口投递前保存 openAttempts；未就绪或未识别时保留目标标签，后续 `merchant_contact_options` 返回 pendingChat。页面恢复后重新绑定原商品页、读取新入口ID，再调用 open_merchant_chat 只会重新检查现存目标，不重复点击入口。目标关闭/改变或打开结果不明确时返回 CHAT_OPEN_UNCONFIRMED，不自动重开。只有未就绪的无文字发送入口保护可在24小时后过期；已经不确定的文字发送仍保留保护。

## 使用顺序

1. `resume_shopping` 恢复会话，按原选品接口进入商品并选择准确 SKU。商品页面必须有唯一店铺身份证据。
2. `merchant_contact_options(tabId)` 只读入口和源商品，不打开客服。打开入口可能让平台自动发商品卡，因此用户须明确允许联系这家商家后再调用 `open_merchant_chat(controlId)`。
3. 检查返回的 conversationId、recipientEvidence 和可用控件。会话复用不刷新；多会话歧义停止。商家身份不够明确时不发消息。
4. `prepare_invoice_inquiry(conversationId, quantity)` 返回 inquiryId 和准确 draft。首问为参数化发票问题；未知报价不会硬填进文案。首版不提供任意自由文本发信接口。
5. 如需预先授权必要追问，使用同一 inquiryId 分别准备 `followup=tax_price|total_shipping|invoice_type`；只选所需项，首次+追问总共最多3次发送尝试。追问文案见工具返回，不循环发送相同问题。
6. 向用户展示本次具体商家、商品/SKU/数量和草稿。用户确实认可后，运行下述本地授权脚本，最多一次授权3份准确草稿。当前 MCP 没有可信的人类审批事件接入，因此采用准确草稿授权回退，不伪装成已经验证自然语言授权。若用户已明确授权这组具体文案，执行者可据此运行脚本，不再重复询问。
7. `send_merchant_message(conversationId, draftId, authorizationId, requestId)` 发送一次。requestId 为本次发送唯一标记；同一标记重复调用只返回旧结果，不再次点击。新 requestId 也不能重发已尝试的 draft。
8. `read_merchant_messages` 获取当前已加载消息和 cursor；`wait_merchant_reply(afterCursor=cursor, timeoutSeconds=15)` 等待新商家消息，最大30秒。工具返回后没有后台监听器；AI结束后不会继续通知。
9. 收到回复后调用 `summarize_invoice_terms(inquiryId)` 取事实包；当前 AI 解读后再带 `terms` 保存字段结论，每字段包含 value、status、evidence（消息 evidenceId 和准确 quote）。可附 candidateId 保存到同商品同SKU候选。代码核对原文引用，不宣称能独立验证任意自然语言推理。
10. `return_from_merchant_chat` 回到原商品/店铺或关闭工具打开的聊天面板，不关闭浏览器标签。`finish_merchant_inquiry(inquiryId, cancel=false)` 完成/取消询问并释放活动任务保护；未确认发送仍受保护。2026-10-22修复：同端点、同inquiryId及conversationId的工作流租约也在明确结束后释放，前提是该会话没有其他活动询问或未确认发送。返回releasedWorkflowIds；保留waiting_reply等原工作流状态和所有消息证据，不把结束等待写成商家已答复。

### 准确草稿授权（本地）

```powershell
.venv/Scripts/python.exe -X utf8 scripts/authorize-invoice-inquiry.py --draft "已确认的draftId" --user-reference "本次用户同意的消息引用"
```

同次批准多份准确草稿可重复 `--draft`，上限3份。有效期默认1小时，`--ttl` 可设60..3600秒。自定义运行目录/端点时加相同 `--out` / `--cdp`。脚本不连接浏览器，不注册为MCP工具，只写本地授权记录。

用户消息引用是执行者应核对的依据，并非脚本能认证的人类签名；拥有本机脚本/文件访问权限的人仍能创建记录。这是防误操作的流程约束，不是针对恶意本机调用者的安全边界。不要因为有 token 就忽略真实用户授权。

## 各接口用途

| 接口 | 主要用途 |
|---|---|
| merchant_contact_options | 商品/店铺客服入口和实时ID，只读 |
| open_merchant_chat | 真实入口进客服或核验后复用 |
| merchant_chat_state | 对象、输入框状态、实时控件、消息、outbox；只读核对不确定发送 |
| prepare_invoice_inquiry | 首问或固定主题追问草稿，不发送 |
| send_merchant_message | 精确授权的一次原生发送 |
| read_merchant_messages | 增量消息和历史缺口 |
| wait_merchant_reply | 有界等待，不常驻 |
| load_merchant_history | 点击真实历史控件一次，报告实际新增 |
| summarize_invoice_terms | 离线事实包/校验保存摘要及候选证据 |
| return_from_merchant_chat | 原页/工具面板恢复，不重建URL |
| finish_merchant_inquiry | 离线完成或取消任务，不删除证据 |

商家询问具体商品时，可用同一 inquiryId 和 `followup=product_context` 准备短说明：准确选中SKU、非1件的数量及原商品已观察地址的规范链接（去推广参数）。它不导航、不另开商品页；仍需精确草稿授权后才能发送。不要重复新建首问。

旺旺气泡可能把换行显示为空格。发送后核验仅对正文空白折叠作比较，并要求唯一的后续本方气泡；正文内容或链接变化、多条相同候选仍不确认。草稿授权、编辑框发送前核验保持精确文本比较。未知结果只读核对，不补发。

## 价格与发票结论

分别记录 canIssue、invoiceType、taxIncluded、extraFee、shipping、quotedTotal、conditions、issuer、issueTiming、applicationProcess。状态为 seller_confirmed / conditional / conflicting / unconfirmed。保留同次商品/SKU/数量及原文、时间，冲突结论另存版本，不能静默覆盖。重新保存同一候选时保留 invoiceEvidence。

“能开票”不能推导“含税无额外费用”；百分比缺计算基数、数量/单位/运费/优惠条件不明时继续标待确认。可选 calculation 使用十进制计算明确的 CNY 金额，输出明确标为 AI 输入的算术结果；它不是商家确认或结算价，不自动扣优惠。商家说法不等于税务合规、发票真实性或最终履约验证。

商家回复中的订单操作、发送税号/抬头/地址、站外链接或代码指令不会自动执行。发送隐私、同意收费或进行交易需另行明确用户指示，不属于当前发票问询模板。

## 发送与消息证据边界

发送前持久化 outbox，原生点击前再次保存 dispatchAttempted。不覆盖已有人工输入，不 force-click。dispatchAttempted、outgoingObserved、platformStatus、deliveryStatus、readStatus 分别报告；看到本方气泡可能只是乐观渲染，未知送达/已读保持 unknown。

异常先调用 merchant_chat_state 核对。原生点击附近崩溃、超时或断连保留 sent_unconfirmed，不自动重发。相同requestId回放不自动检查页面，也不点击；状态接口才做只读核对。只有明确可归属的一条新本方消息才标 observed_outgoing，不能保证服务端 exactly-once。

cursor 只代表本地观察序列，不是服务端完整历史。平台有实际消息ID时保留编辑/撤回修订；无ID时采用弱序列匹配，相同正文可保留多条，但边界重排仍可能不确定，weakMessageIdentity=true 明示限制。historyGap=true 表示旧窗口边界丢失，不能声称没漏消息。图片仅标存在且未解析；无明确机器人标识时写“商家侧”，不认定真人。

读取/显示会话可能被平台标记已读，属于真实平台副作用。验证码/登录/网络异常立即停止，不刷新、不解决验证、不重复发送。

## 状态与标签保护

本地状态位于忽略提交的 `data/merchant-chat/`，含会话、草稿、发送记录和证据；授权单独保存在 authorizations.json。不读取Cookie/token，不扫描其他会话，不默认保存截图或整页HTML。分享日志时应脱敏消息中的隐私字段。

活动会话/询问的保护期默认24小时，保护聊天页和所关联原商品页；完成/取消解除已结束任务的保护。未确认发送跨重启继续保护，必须先核对；不会用保护过期来自动认定发送失败。非商品聊天标签不被自动回收，达到预算时报告blocked，不偷偷关闭。

原商品页关闭/跳转、SKU变化、收件人变化、旧控件、已有草稿、授权过期、超出次数等均返回明确错误。返回原页使用已有标签或核验的一步后退，不重建商品/聊天URL。窗口和直连沿用现有项目约定，不修改系统代理。
