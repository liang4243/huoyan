# 标签数量上限与自动回收

2026-10-16。适用于当前Python Playwright控制器和货眼MCP，不依赖重启Chrome或新增扩展。

## 默认行为

- 默认上限 **10个**，统计连接的专用Chrome会话内全部标签，包含首页、结果页、店铺页、商品页及其他标签；不是每种页面各10个。
- 优先复用同一商品已有标签，读取不刷新；真正需要经页面链接新开时，对实际target=_blank链接及表单先尝试预留1个位置。例如已有10个标签，先回收到9个，再点击真实链接打开第10个。
- 接管网站真实打开的新标签后记录来源和工具所有权，在线动作完成后再次检查预算。商家脚本临时打开的窗口可能在接管前短暂超过上限；这不是硬性的浏览器级窗口拦截器。
- 达到10个且没有新开需求时保持10个，不为凑数反复关闭、重开。纯读取状态不会自动关闭标签，没有常驻定时扫描；用户自行新开的页面在后续动作或显式清理时检查。
- 默认只回收货眼在本功能启用后，经实际点击新开的商品页，按最近被货眼绑定/读取时间排序。复用页面会更新最近使用时间；推广链接仍按商品ID去重。

## 哪些页面会保留

当前明确绑定的页、记录中的返回来源页、首页/搜索/店铺等非商品页、手动或来源不明的标签不会被自动回收。功能启用前已存在但没有新开记录的商品页同样受保护，不能凭标题猜测是谁打开的。

可检测到有焦点、未提交文本编辑、正在播放媒体、onbeforeunload处理器或可见研究面板的页面会跳过。工具页被导航到另一个商品时不沿用旧商品的清理授权。此检查不能证明所有站点临时状态都能被识别；保留重要页面时应避免让它成为闲置工具页。

如果全部页面受保护，报告 `blocked=true`，达到上限的已识别新标签链接返回 `TAB_LIMIT_REACHED`，不投递点击。已有商品复用、当前商品研究和返回结果页仍可使用。降低上限会立即尝试清理，但保护规则可能让实际标签数仍高于新值；返回 `configured=true` 仅代表配置已保存，`confirmed=false` 表示尚未达到数量目标。

## 关闭前后的数据

关闭前只读提取候选页已加载的商品文字、SKU、报价及commerce证据，原子写入既有 `product-tabs.json` 缓存；写入失败或出现登录/验证/未知状态就停止本轮清理，不先关页再补缓存。不刷新、不下载新资源、不切换SKU，也不把缓存标为实时价格。

关闭后更新商品与标签映射、删除该页的短期购物控件与返回映射，并释放控制器持有的CDP监听会话。后续读取该商品优先返回缓存，没有可执行控件。要重新访问，仍须从真实页面商品链接进入，禁止直接重开缓存URL。

缓存不是完整浏览器会话备份：网页内临时交互、滚动位置和未被解析的状态不保证还原。此功能限制存活标签数量，未做Chrome堆内存分析，也不宣称已经定位或修复内存泄漏。

## MCP接口

```json
{"name":"set_tab_limit","arguments":{"maxTabs":10}}
```

上限允许2到50，立即保存配置并按新值尝试清理。无需tabId；使用与其他工具相同的out目录和cdp地址。

```json
{"name":"trim_product_tabs","arguments":{}}
```

按已保存上限立即检查。不会把所有闲置商品页清空，只清理超出的数量。

`shopping_state`以及动作返回的`tabBudget`包含maxTabs、openTabs、关闭列表和blocked/overLimit。`closedTabs`记录实际确认关闭的tabId、productKey及缓存状态，不把计划关闭算作完成。纯读取的lastCleanup是历史记录。

配置、工具新开身份和最近使用时间保存在out下的`tab-budget.json`，默认`data/tab-budget.json`；不同out目录互不共享记录，CDP地址变化时不沿用工具所有权。该运行文件已忽略提交，不存Cookie或密码。

重新连接货眼MCP加载set_tab_limit和trim_product_tabs工具；默认10个的Python逻辑随下次调用生效，Chrome无需重启。后台运行/窗口恢复仍按用户要求暂停，本功能不会恢复真实购物窗口。
