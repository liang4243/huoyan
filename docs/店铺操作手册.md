# 店铺操作手册

## 进入哪一家店

1. `shopping_state` 查看现有标签页，`activate_shopping_tab(tabId)` 明确激活并绑定。
2. 商品详情里读取实际进店入口，调用 `open_product_shop`；存在多个入口时传当前 controlId。
3. 或在首页/全站结果页调用 `search_products(keyword=店名, target=shops)`。只有实际发现并核验“店铺”搜索模式才能提交；下拉模式菜单未展开时，先用 `click_shopping_control` 点击实际 search_target_menu，再读取新选项。没有入口则返回 UNSUPPORTED，不拼接店铺搜索 URL。
4. `list_shops` 列出已加载的店铺入口，用 `open_shop(controlId)` 进入准确的一家。同名店不会自动合并；店铺入口列表也可能包含当前商品的进店链接，不等于完整店铺搜索结果。
5. 已经打开的店铺可直接激活。进店时会检查现存页面的店铺身份；唯一匹配时复用且不刷新，不把店内搜索页改回首页。多个匹配标签页且当前页不属于该店时停止，由 AI 明确选择现存页。

店铺身份是可观察的页面证据：数字店铺域名/实际链接中的店铺 ID、已识别天猫域名，以及页面确实暴露且唯一的 sellerId。未知字段为 null。域名身份并不证明商家资质；无法证明相同的自定义域名/跳转别名不强行合并。当前支持数字淘宝店铺域名、同 ID 的 mall.taobao.com / store.taobao.com 入口及已识别天猫子域名。

## 入店后先向 AI 返回有哪些选项

入店、激活店铺和操作后的响应自动包含 `state.shop`；`shop_state` 可单独只读查询。

它包括店铺身份、当前页面阶段、关键词及查询证据、真实栏目/分类、排序筛选、页码、已加载商品、availableActions、控件状态和实时 controlId。未展开的子分类和菜单选项不会提前编造。动作响应更新后弃用旧 ID。

rendered / inViewport / actionable 是当时的布局、可见和命中情况，操作仍受 Playwright 原生可点击检查、焦点和控件身份核验约束。出现在 DOM 中不等于现在能点击。

## 操作接口

以下接口继承通用 tabId、cdp、out、delayMin、delayMax。默认操作间隔仍为 12～25 秒。

| 接口 | 参数 | 用途 |
|---|---|---|
| shop_state | tabId | 只读本店选项和当前状态 |
| list_shops | tabId | 读取实际店铺候选、身份与入口 ID，不导航 |
| open_shop | controlId | 真实点击进店或复用匹配店铺标签页 |
| search_shop_products | keyword、可选 controlId | 配对并使用本店搜索框，核验同店铺、查询词证据和结果/无结果 |
| open_shop_section | controlId | 点击实际店铺首页、全部商品、上新等栏目 |
| open_shop_category | controlId | 点击实际分类或展开分类，返回更新选项 |
| open_shop_product | controlId | 进入实际商品卡，优先复用商品标签页，同次返回详情/SKU 选项 |
| return_to_shop_results | tabId | 返回此次访问来源店铺列表，核验上下文，单独报告滚动位置恢复情况 |

`open_product_shop` 保留兼容，内部使用统一进店逻辑。

`search_products(scope=shop)` 复用同一套本店核验；优先使用不会漏传 scope 的 `search_shop_products`。多个本店搜索框需提供刚返回的准确 controlId；输入框与按钮仍不能唯一配对时，提交前停止。全站框即使也叫 q，也不会当成本店框。

排序沿用 `set_sort(field=comprehensive|sales|price|newest)`，价格可带 direction=asc/desc。newest 只点击真实排序区域的“新品/上新”，不把店铺“上新”导航栏目当成排序。

筛选沿用 `set_filters`，商品卡读取沿用 `list_products`，跳页沿用 `go_to_page`。只有下一页/上一页按钮时，使用 `click_shopping_control` 点击其当前 ID；不猜页码或造地址。`load_more` 每次只做一次有限滚动。

## 一次完整的本店选品

1. 从原商品实际进店入口 `open_product_shop`。
2. 先看返回的 `state.shop`，确定本店搜索、分类、排序是否存在。
3. `search_shop_products(keyword="PLA")`；检查 confirmed=true、店铺身份及 queryEvidence。无结果时调整本店关键词，不自动转全站。
4. 按实际控件排序、筛选、分类或翻页。每一步使用其新响应的 ID。
5. `list_products` 阅读当前商品卡，使用 `open_shop_product(controlId)`。
6. 先看 `state.detail` 的规格分组和可用操作，再选准确 SKU，读取参数、评价、图片，必要时保存候选。
7. `return_to_shop_results` 返回此次来源列表。确认 contextRestored 与 scrollRestored，不假定浏览器已经完整恢复。

## 证据和失败处理

- 商品卡标记 shop-products、recommendation 或 unverified；识别出的推荐区域不能作为本店结果进入。未知区域只表示尚未证明归属，不能宣称商品一定属于本店。
- open_shop_product 的 shopEvidence 记录来源容器、来源店铺，并比较详情实际店铺链接；detailShopVerified 仍是页面链接证据，不是独立商家认证。
- 保存候选附加 shopDiscovery，记录当次来源店铺、关键词、分类、排序筛选、页码和时间。多次访问历史分别保留；从全站重新进入同一商品会更新最新返回来源。
- `data/shop-tabs.json`、`data/shop-visits.json` 是本地运行数据，已忽略。映射随在线读取更新；不以旧缓存的控件点击页面，不自动打开关闭的标签页。
- SCOPE_MISMATCH / confirmed=false 表示搜索或操作离开本店或缺少成功证据，停止后续动作，读取状态。输入框变成新词本身不能证明查询成功。
- SOURCE_CHANGED 表示原列表关闭、URL/历史改变，或返回后的查询/分类/排序/筛选/页码不一致。不会重建旧 URL。上下文变化可能在切回原页后才被发现，此时保留该页供检查。
- 滚动位置单独核验，不自动声称或强制恢复。完整结果数量、服务端筛选准确性、商家资质、准确 SKU 到手价保持未核实。
- 当前仅操作顶层文档。iframe 数量与 unsupportedFrames 明确返回；嵌入框架内尚未适配的按钮不会被当作可用功能。
- FOCUS_CHANGED 后必须明确重新激活；验证、登录或网络异常停止实站操作，不自动刷新。
