# 双收藏与快速找回

2026-10-22。用户要求同时支持“货眼本地收藏”和“淘宝账号收藏”，两者分别返回 `scope=local` 和 `scope=taobao`，不会自动混成同一份收藏。

| 行为 | 本地收藏 | 淘宝账号收藏 |
|---|---|---|
| 保存位置 | 仓库 data/local-favorites.json | 淘宝账号的收藏夹 |
| 保存内容 | 商品 ID、去推广 URL、标题、历史 SKU/价格摘要、备注、标签 | 页面真实收藏按钮对应的商品 |
| 是否需要选完规格 | 不需要，未选完明确标记 | 商品级收藏，不能当作收藏了准确 SKU |
| 离线查询 | 可以 | 只能看实际已加载页面，不假称完整账号列表 |
| 删除 | 只删除本地条目 | 专用接口 selected=false，真实取消收藏 |
| 标签关闭之后 | 默认返回本地缓存 | 从现有收藏夹入口和实际商品卡点击进入 |

收藏不表示锁住标签。商品页仍按原来的标签预算回收规则处理；收藏记录保留。回收后需要现场数据时依然遵守页面内导航，不直接重开保存的商品地址。

## 本地收藏接口

- `save_local_favorite(tabId, note?, tags?)`：从绑定的商品详情页保存。按平台+商品 ID 去重，同一商品不同推广链接不重复；最多保留 50 份按选中 SKU 去重的摘要。再次保存时，不传 note/tags 会保留原值，显式空值用于清空。
- `list_local_favorites(query?, limit=50)`：离线按标题、商品 ID、SKU、备注和标签查找，最多返回 200 条。不连接浏览器、不整理/关闭标签。
- `remove_local_favorite(favoriteId)`：只删除本地收藏，不操作账号收藏。
- `open_local_favorite(favoriteId, fresh=false, tabId?, maxScrolls=3)`：已有同商品标签时直接激活读取，不刷新、不偷偷切回保存的 SKU。标签关闭或浏览器不可用时，默认返回明确标记 stale 的缓存。

`fresh=true` 表示通过页面找回现场数据：已有标签仍优先；否则从指定购物页的真实入口进入淘宝收藏夹，查找实际商品卡再点击，不直接使用本地 URL 导航。如果本地收藏没有同时收藏到淘宝，可能在账号收藏夹找不到；接口如实返回缓存与未找到的覆盖范围，不冒充已打开商品。

本地快照是历史证据，展示价不是默认准确到手价，库存和优惠资格不得沿用为实时事实。收藏了商品也不代表当前规格就是原来保存的规格；进入后先读同次响应中的 SKU 清单再决定。

## 淘宝收藏接口

1. `favorite_options(tabId)` 读取真实控件和状态；普通 `shopping_state` / 详情响应也会返回独立的 `favorites` 区域。收藏 ID 只用于收藏专用接口，不能混进通用点击或其他页面的 ID。
2. `set_taobao_favorite(tabId, requestId, selected=true, controlId?)` 设置明确目标状态。页面已经满足时零点击；有多个实际入口时必须选当前 ID。仅允许商品页，选中状态依据可见“收藏/已收藏/取消收藏”或 aria-pressed，不从图标颜色猜测。
3. `open_taobao_favorites(tabId, controlId?)` 优先复用唯一现存收藏夹标签；否则点击当前真实收藏夹入口，不构造地址。当前实站发现的是顶部入口 `i.taobao.com/my_itaobao/itao-tool/collect`，另兼容已识别旧收藏页。入口可能在原标签导航，商品页需保留时可先切到已有首页/结果页再进入收藏夹。
4. `taobao_favorites_state(tabId)` 读取当前已加载收藏商品的标题、ID、展示价、入口 ID。推荐区商品不算账号收藏；推广链接按商品 ID 去重。
5. `find_taobao_favorite(tabId, productId? / keyword?, maxScrolls=3)`：先查已加载列表；有实际“收藏夹内搜索”输入/按钮配对时才用关键词搜索。全站顶部搜索框不能当作收藏内搜索。没有合适搜索框时仅在此页有限滚动，最多 5 次，间隔随机 0.5–1.2 秒，每次随机 0.5–2.5 个视口，实际到底或不能继续就停，到底后略向上回滚。找不到只表示本次加载范围未观察到，不证明账号没有收藏。
6. `open_taobao_favorite(tabId, productId? / controlId?)`：匹配当前实际收藏商品卡，优先复用同商品已有标签，否则点击真实商品链接进入，立即返回最新详情/SKU 选项。`return_to_results` 可以回到此次收藏来源页或核验的一步后退。

示例：

```json
{"tool":"save_local_favorite","arguments":{"tabId":"当前商品页ID","note":"准备比较的工具","tags":["工具"]}}
{"tool":"favorite_options","arguments":{"tabId":"当前商品页ID"}}
{"tool":"set_taobao_favorite","arguments":{"tabId":"当前商品页ID","requestId":"稳定且唯一的本次请求ID","controlId":"刚返回的收藏按钮ID","selected":true}}
```

之后从任意现有购物页读入口，调用 open_taobao_favorites → find_taobao_favorite(productId) → open_taobao_favorite(productId)。也可 list_local_favorites(query) → open_local_favorite(favoriteId)。这些是 MCP 工具参数示例，不是任意 JavaScript 或 URL 接口。

## 重试、焦点与限制

`requestId` 绑定商品 ID、原标签和目标状态；复用它请求另一个目标会报冲突。每次真实点击前在 `favorite-actions.json` 写日志。点击结果不明时，不换一个 ID 再点：同请求只读核对，直到实际页面显示期望状态；不伪造成功、不把临时 toast 当作独立服务端持久化证明。

结果不明的原商品标签会加入持久保护，防止切到其他页面后被 LRU 回收；核对确认后恢复正常预算规则。收藏控件缓存会随标签回收清理。升级迁移也保留本地收藏及账号操作日志，同请求 ID 的冲突记录会停止迁移，不覆盖。

收藏是用户明确授权的专用功能例外；通用研究/点击接口依然不执行收藏、加购、下单、支付或领券。收藏夹按独立 `favorites` 页面类型绑定焦点；当前/来源/手动标签、登录状态与标签预算照旧保护。登录、验证码、异常、页面/目标变化停止，不 force-click 或删除遮罩。

仅支持当前 DOM 实际识别的收藏按钮、入口、商品卡和收藏内搜索。不支持未识别 iframe 内操作、批量删除/批量收藏、店铺关注、收藏清单管理，也不宣称翻完全部历史收藏。无法识别时应报告 unsupported/未加载并保留现有页面。
