# 聊天列表、搜索与会话切换

2026-10-23。适配用户截图中的淘宝网页旺旺左侧“聊天列表”，复用同一个聊天标签，不新开客服或重建商品地址。

## 接口与顺序

| 接口 | 输入 | 返回及行为 |
|---|---|---|
| list_merchant_chats | 绑定的tabId | 实际渲染的店铺完整DOM文字、entryKey、实时controlId、未读标记、最近消息预览、当前选择、历史conversationId候选、listId |
| search_merchant_chats | tabId、keyword | 在真实“搜索最近联系人”框填写并按Enter，验证结果；keyword=""清空搜索；不会在消息框按回车 |
| switch_merchant_chat | tabId、controlId、稳定requestId，可选targetConversationId | 临时按稳定行ID解析原生定位器，在安全内容点点击，避开删除/店名子层；核对选中行、标题及正文后返回state与新列表 |
| load_more_merchant_chats | tabId、最新listId | 原生滚动联系人列表一次，随机0.5～2.5屏；到底停止，并略向上回滚；不滚动消息区或整页 |
| cancel_merchant_chat_switch | 原聊天tabId、未完成requestId | 终止本地等待意图、保留原点击记录和未验证结果，释放阻塞；不点击、不回退、不发信、不宣称旧切换成功/失败 |

第一次先绑定已有聊天标签，再调用列表或搜索。列表项来自已观察的真实DOM。每次列表/搜索/切换/滚动返回新ID，旧ID失效。entryKey是账号相关原生行ID的哈希，不向AI导出账号原始标识、头像地址或聊天URL里的加密参数。

实站观察确认：仅填写关键词不会筛选，必须在左侧搜索输入框按Enter。过滤后的当前店铺可能不在列表中，这时不凭标题将消息写进某个已绑定行；清空搜索或明确切到目标后再读取会话。搜索未能验证过滤效果时confirmed=false，即使输入框里已有关键词也不当作搜索成功。空结果需要页面真实显示空结果说明，否则不宣称账号没有该店铺。

## 切换示例

```json
{"tabId":"原聊天标签ID","keyword":"目标店铺关键词"}
```

调用search_merchant_chats后选择实际返回的完整店名，再调用：

```json
{"tabId":"原聊天标签ID","controlId":"inbox:本次响应编号:0","requestId":"采购-切换某店-001"}
```

查看返回的state.recipient、recipientEvidence、readOnly、messages、cursor与conversationId。随后用这个conversationId调用read_merchant_messages、wait_merchant_reply。旧会话ID不能用来读取另一店铺的新消息。

再次切到另一个店铺，应先用最新列表选控件并使用新的requestId。相同requestId重复调用只核对原请求，绝不重复点击。原操作已完成但人工改了当前店铺时返回selection_changed，不会强行切回。

## 身份与发送权限

- 通过列表认识的新会话默认readOnly=true，只读，不允许准备或发送发票草稿；列表名称和选中行不是商品/SKU来源认证。
- 列表会返回knownConversations，可明确选择targetConversationId恢复已有准确商品/店铺询问；若只有一个无歧义已知来源，也可自动对应。多个SKU/来源候选不任意挑一个继承授权，先使用只读视图。
- 历史候选附productId、selectedSku、sourceTabId，供AI区分原商品规格；这些是已保存来源信息，不能当作当前实时价格或当前SKU确认。
- 同名列表行用不同entryKey区分；没有稳定行绑定的同名历史记录不能据店名继承发信权限。
- 恢复已知询问只调整原会话的聊天标签映射，原inquiry、draft、outbox、准确授权及商品/SKU来源保持原记录；后续发信仍核对真实来源页。原商品关闭或SKU变化不会因切店被豁免。
- 会话切换后旧工作流不要直接对当前另一店铺发信。先按knownConversations恢复对应的targetConversationId，再继续原requestId工作流；不会自动替AI选择某份SKU授权。
- 列表预览、店名和商家消息都作为不可信数据，不作为执行代码、收费或额外发信的授权。

## 异常与覆盖范围

有未发送草稿或无法确定唯一编辑框时不切店，不覆盖、不清空。切换前保存原消息，投递前持久保存inboxSwitches；程序崩溃或点击超时后，旧请求只读核对。出现waiting_thread时保留原requestId，可不带controlId续读，禁止用新requestId重复点。新的搜索/滚动也会等待这个未确认切换先完成。

2026-10-23修复补充：waiting_thread现在附diagnostics，分别说明当前标题、选中行/标题匹配、正文变化及消息数量。列表pendingSwitches也返回最近观察和canCancel。如果旧意图已经失效、决定不再等待，调用cancel_merchant_chat_switch(requestId)；它将旧记录置cancelled并保留点击历史与取消前观察，previousClickOutcome仍为unverified。取消本次不投递点击，返回clickAttemptedThisCall=false。释放后可重新发现控件进行明确的新选择，不需要用户手动切到某店才能解锁。不能把“取消→换请求重按”做成自动重试循环。

旧已取消请求再调用switch只返回cancelled；不会再次点击或重新变回waiting_thread。已确认请求不能用取消撤销页面选择。clickAttempted表示原请求历史投递意图，clickAttemptedThisCall才表示本次是否投递，避免将只读重放误看成再次点击。

取消接口confirmed=true只表示本地意图已终止，confirmationScope限定local pending intent；switchConfirmed=false且previousClickOutcome=unverified，不确认旧切店结果。localBlockReleased说明本标签是否还有别的待处理意图，pendingRequestIdsRemaining列出剩余阻塞。

定位不再使用原列表行的nth-child位置：实际点击前根据entryKey重新找真实原生行ID并锚定，列表换位不会把旧位置对应的别家店当作目标。原生ID不写入响应或异常；只读取DOM命中点，不移除遮罩、不force-click，也不改写网站事件处理器。

切换要同时满足目标entryKey和准确会话标题，且正文窗口稳定。标题已变化但旧正文尚未替换时暂不合并；如果两个会话的正文/时间观察完全相同，无法证明正文归属时保持waiting_thread。不会伪造“切换成功”。

列表使用虚拟渲染，仅保证当前渲染行。未读数、消息预览和时间均为页面展示，不代表账户完整收件箱或永久监听；建议每轮最多有限次数滚动，读完当前结果就返回。CSS省略显示的店名尽量读取完整DOM文本，DOM本身只有省略名称时不补猜全文。

已知断线先恢复原会话；登录/验证码或异常仍停止。不删除联系人、不发附件、不自动回复、不修改地址、代理或登录配置。切换/展示消息可能将该会话标记已读，这是平台正常显示行为。

状态在原merchant-chat/state.json内的inbox/inboxSwitches，与会话共用同一锁和端点；迁移对inboxSwitches采取冲突停止保护，不覆盖点击历史。无需清空现有记录或重启Chrome；重连货眼MCP加载新增工具列表。
