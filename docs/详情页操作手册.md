## 进入后先告诉 AI 有哪些选项

从实际结果卡进入商品、激活并复用已有商品页、调用 inspect_product 读取实时商品时，同次响应自动带上 detail：商品身份、当前 SKU、规格分组、已选/禁用选项、栏目、图片、研究浮层、滚动容器、可用操作及当前控件 ID。初次读取不会改选 SKU 或展开所有栏目。

AI 先看这份清单，按用户需求决定下一步。清单只表示当前加载出来的内容；未展开的评价筛选不提前假定存在。requiresSelection=true 的规格组按 selectionIndex 顺序传给 select_sku；单选组会另外列出。禁用状态表示页面控件状态，不是服务端库存保证。

动作返回更新后的 state.detail。获取新状态后，旧 controlId / sectionId / imageId / panelId / containerId 都应弃用。缓存只有历史商品数据，没有可执行控件，不能拿缓存 ID 点击页面。

## 接口与常用操作

以下接口带当前已绑定的 tabId，并继续接受 cdp、out、delayMin、delayMax。默认操作间隔 12～25 秒。

| 接口 | 参数 | 作用 |
|---|---|---|
| detail_state | tabId | 只读详情状态、规格与实际可用操作 |
| read_product_evidence | includeLevelImage，默认 true | 汇总店铺评分/等级、交易指标、配送/服务、参数、图文和已加载图片；唯一且完整可见的真实等级图标可作为 MCP 图片返回；不滚动或切栏目 |
| read_shop_reputation | controlId 可选 | 无ID只读当前店铺评分卡文字；传当前信誉悬浮ID原生hover展开，不点击进店或客服 |
| product_image_overview | imageSources=sku/gallery/description，maxImages=1..48，offset，allowScreenshot=false | 默认每页24张编号概览，不滚动/截图/切SKU；不可读图标缺失。仅用户明确允许时true启用可见截图回退；返回overviewId和nextOffset |
| read_product_image | overviewId，index | AI看概览后按对应编号取单图，核验标签/商品/SKU/图源；优先返回已加载资源原尺寸 |
| open_detail_section | sectionId | 切换正文评价/参数/图文详情或图片区参数/图集，按区域区分同名按钮 |
| read_product_parameters | 无额外参数 | 读取结构化参数和原文；标明商品通用参数，不把全颜色列表当作已选颜色 |
| open_reviews | controlId 可选 | 点击实际查看全部评价入口；面板已开则直接返回；最多等待5秒原生可操作性，不强制穿过遮挡，仅面板实际打开才 confirmed=true |
| read_reviews | limit，默认 20，上限 100 | 读取已加载评价的正文、日期、显示规格、追评和图片；打开面板后优先读取面板样本 |
| open_review_menu | controlId，interaction=click 或 hover | 一次真实点击或悬浮打开已发现的排序/款式菜单；默认点击，不自动交替重试 |
| set_review_filter | options=[{controlId,selected}] | 选择实际存在的评价筛选或排序项，核验选中状态；单选取消需选择真实替代项 |
| load_more_detail | containerId，maxSteps=1..5 | 滚动实际容器，每步 0.5～2.5 视口；无新增、重复、未移动或到底停止，到底稍往上滑 |
| close_detail_panel | panelId | 通过真实关闭按钮或已确认的服务展开入口收起本工具打开的面板，不关闭未知聊天/验证浮层 |
| view_product_image | imageId | 点击实际图片/缩略图或已发现的图片前后切换控件，核验主图/选中状态/面板变化 |
| read_product_questions | limit，默认 20，上限 100 | 读取已加载问题与回答 |
| expand_question_answers | questionId 或 controlId | 点击对应问题的更多回答，核验新增回答或问答面板；不随便点同名第一个按钮 |
| read_delivery_services | controlId 可选，interaction=click 或 hover | 无 controlId 时只读配送来源和服务说明，目的地脱敏；传实际入口默认点击展开，已打开则直接读，不修改地址 |
| set_quantity | quantity=1..1000 | 修改唯一启用的数量框，遵守页面 min/max 并核验；不加购下单，不保证单价变化 |
| open_product_shop | controlId 可选 | 使用实际进店链接；相同已开店铺入口复用原页，不刷新 |

已有 select_sku、read_selected_offer、save_candidate、compare_candidates、return_to_results 继续使用。商品页仍不能直接执行全站搜索、结果排序或继续点推荐商品。

## 一个完整的详情研究流程

1. 从结果卡进入，或 activate_shopping_tab 激活已有商品页，直接读取响应内的 detail 选项。
2. 根据用户条件，从实际规格组选择准确 SKU；核验 select_sku 与 read_selected_offer。
3. 选择正文参数栏目，再 read_product_parameters；图片区的“参数”是另一个区域，不能混用。
4. open_reviews，读取面板返回的实际筛选项；需要时间排序等菜单选项时先 open_review_menu，再使用其新返回的 controlId。
5. read_reviews 读取有限样本，必要时用面板自己的 containerId 执行 load_more_detail；关闭面板后再操作下面的商品内容。
6. 读取问答、按需展开特定问题，查看图片和配送/售后。
7. save_candidate 保存当前准确规格和有来源的参数、评价样本、问答、服务及图片信息，再 return_to_results。

## 可见性与失败处理

- rendered 表示 DOM 有布局；inViewport 表示扣除滚动容器裁剪后与视口相交；actionable 还检查了命中测试与禁用状态。这些是当时的观察，执行仍由 Playwright 的原生可点击性检查把关。
- needsScroll=true 需要先滚动到可见位置。工具会核验商品、SKU、面板和目标身份；滚动带来的正常懒加载不等于允许点击改变身份的控件。
- blockedByOverlay=true 时，应先识别并处理挡住它的面板。面板开着时不要滚动背景正文。
- 详情点击前先按需滚到实际控件，中心被挡住时再正常居中滚动，保留遮罩及原生点击检查。原先的1.5秒预检延长为5秒，以容纳短暂的加载遮挡；之后依然核对商品、SKU、面板和控件身份，再投递一次点击。
- CONTROL_NOT_ACTIONABLE 表示原生预检超时、尚未投递点击。MCP 会返回同名 code，error 中附 inViewport、blockedByOverlay、hitTag、visibility 等当时可读取的诊断，不输出遮罩文字或买家信息。错误后的 nextAction 要求先检查状态，不自动重试；该错误不等于账号退出或验证码。
- confirmed=false 表示结果未确认，不是成功。不要循环点击。异常可能出现在部分编辑之后，应先检查当前状态。
- UNSUPPORTED 表示没有真实入口；STALE_CONTROL 表示控件状态改变；UNOWNED_PANEL 表示不是工具可关闭的面板；可见模式的 FOCUS_CHANGED 后必须明确重新激活。
- 遇登录、验证、网络异常停止，不刷新、不尝试解除验证。


## 图片与候选证据

select_sku_and_collage 新增 imageSources，可选 gallery、description、review，默认前两者。它只截取页面已渲染图片，不拼接高清地址。输出记录来源、自然尺寸、清晰度提示、时间和 SKU 关联状态；商家图片与买家图片分别标记。图片可能被多个 SKU 共用，默认 skuAssociation=unverified。

save_candidate 的 researchEvidence 记录当时已加载的参数、评价样本、问答、服务、配送来源、图片和所选规格。商家宣传、买家反馈与当前报价均为页面证据；最终到手价、运费、优惠资格、服务端库存仍未核实。后续改变 SKU 不会让旧候选变成新规格的证据。

商品与 detail 会自动带上 commerce，read_selected_offer 和候选证据也保留它。店铺综合评分不等于店铺信用等级；“已售1万+”“回头客379人”“超400人加购”分别保存原文、范围、近似值和单位。详情页回头客可能是商品范围，不能塞入店铺回头客。具体字段与图片读取流程见 [商品信息证据手册](商品信息证据手册.md)。

当前实现依据本轮实际淘宝模板及隔离测试。天猫、跨域框架、视频播放、未出现的优惠/追评等能力须另行实测；没有真实入口时不宣称兼容。加购、收藏、下单、支付、领券、发送消息和修改地址不在这些研究接口中。
