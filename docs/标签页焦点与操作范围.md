# 标签页焦点与操作范围

2026-10-17 用户授权更新：窗口最小化或没有淘宝标签时，先调用 `resume_shopping` 自动恢复专用窗口；空会话只打开固定淘宝首页，不再询问用户手动恢复或打开。已有页面不刷新，手动页面不覆盖，保持10标签上限；登录/验证码仍停止。此规则覆盖旧的“暂停窗口恢复”和“仅首次允许首页”限制，商品/搜索地址仍不得直接重开。显式切页使用 `activate_shopping_tab(background=true, restoreWindow=true)`。见 [自动恢复购物会话](自动恢复购物会话.md)。

更新：2026-10-15。适用于货眼 MCP 和 Python 控制入口；新增 `activate_shopping_tab`、`return_to_results` 两个工具。

2026-10-16 状态补充：后台读取和按需窗口恢复的试改代码已保留，`activate_shopping_tab` 当前接受 background（默认true）和 restoreWindow（默认false）。background=true 允许读取已绑定隐藏页面的已加载内容；原生交互可能尝试恢复窗口，不能保证 Windows 将窗口调至前台。用户要求先跳过此问题，本轮不继续修复或操作原窗口。下面要求可见性及手动切走停止的流程描述针对 background=false；要沿用该流程应显式传 false。窗口状态 normal/maximized 不代表已在最前面，系统焦点和遮挡未核实时保持 unverified。参见（私人验收记录未随发布包含）。

## 操作流程

1. `shopping_state` 不带 tabId：只读列出已有购物页及绑定状态，不切换、不刷新。
2. `activate_shopping_tab` 带目标 tabId：切到该已有标签页，核验可见性，明确绑定。
3. `shopping_state` 带这个 tabId 获取当前控件，再调用相应购物工具。
4. 选择商品卡片时，复用已有商品页或接管真实链接打开的商品页，并记录来源。
5. 在商品页研究规格、价格、图片、参数和评价，保存候选。
6. `return_to_results`：切回关联的原结果页继续研究；同标签进入的商品通过核验过的浏览历史后退。

排序和筛选应回原搜索结果页，保留关键词、筛选条件和页码。首页用于首次搜索或首页商品入口。

```json
{"name":"shopping_state","arguments":{}}
```

```json
{"name":"activate_shopping_tab","arguments":{"tabId":"已有结果页ID","background":false}}
```

```json
{"name":"set_sort","arguments":{"tabId":"同一结果页ID","field":"price","direction":"asc"}}
```

```json
{"name":"return_to_results","arguments":{"tabId":"当前已绑定商品页ID"}}
```

## 页面允许的操作

| 页面 | 操作 |
|---|---|
| 首页 | 搜索、搜索建议、点击首页商品 |
| 结果页 | 搜索、排序、筛选、分页/加载更多、选择商品 |
| 店铺页 | 按实际表单进行店内/全站搜索，执行页面确实提供的排序、筛选和商品入口 |
| 商品页 | 选规格、读取报价、参数/评价等内容页签、图片/合图、保存候选、进入店铺或点击真实首页入口 |

商品页不允许借页面上的全站搜索框开始新一轮搜索，也不允许借推荐商品卡片继续选其他商品；先回对应结果页。

读取当前页面同样遵守绑定；读取本地商品缓存、候选比较和进度记录可以离线执行，不需切换。旧 MCP 的通用点击、采集、商品读取和合图入口也执行相同 Python 焦点检查。此约束不限制用户自己操作浏览器。

## 焦点变化后的处理

- `NEEDS_TAB_SWITCH`：目标不是已绑定标签页，先明确调用激活工具。
- `FOCUS_CHANGED`：标签页隐藏、手动切走后又回来、或页面被非预期替换，停止原动作。重新激活代表开始一次新的明确操作。
- `WRONG_PAGE_TYPE`：当前页面不支持这个动作，切换到正确的已有页面。

随机等待期间持续核验，点击、输入、规格选择和滚动之前再次核验。切走时停止，不自动把窗口抢回来。已完成的部分操作保留，不通过刷新或再次提交来补偿。

网站真实点击产生的页面跳转、弹出商品页和用户明确选择的已打开商品复用属于已授权导航，会核验目标并接管；意外或不明确的新标签需要显式选择。已关闭的原结果页不自动重开。功能上线前已经存在、没有来源记录的商品页，需显式选中已有结果页，不能猜测它来自哪次搜索。

绑定元数据保存在 out 下的 `focus-state.json`。只记录 CDP 地址、标签 ID、监听标识、计数和返回关联；不读 Cookie、密码或登录凭证。运行文件已加入默认忽略列表。

## 原生可见性

项目固定 Playwright 1.64。CDP 连接采用其公开参数 `no_defaults=True`，保留 Chrome 原生焦点/可见性，避免 Playwright 默认焦点模拟让后台标签仍报告可见。监听 `visibilitychange` 的计数放在独立脚本环境，不写入商品 DOM，不伪造 `document.visibilityState` 或 `navigator.webdriver`。

这里管理浏览器标签页及其原生可见状态，不锁定系统键盘/鼠标焦点。窗口最小化或被完全遮挡也可能被 Chrome 报为隐藏；无法确认可见时停止。其他同时控制同一个 Chrome 的工具可能影响其状态，应先重新读取绑定状态。

## 验证记录

`npm run test:focus` 用普通方式启动的可见隔离 Chrome，CDP 通过 no_defaults 连接；购物页面全部由本地夹具响应。8 项测试通过：

1. 没有显式绑定时拒绝操作，后台完整读取也被拒绝。
2. 等待期间切到其他标签，原排序按钮不点击，焦点不被抢回。
3. 切走后又切回来仍拒绝；显式重新激活后可继续。
4. 焦点失效跨 Python 控制器重新连接保留。
5. 商品页搜索/排序被拒绝，旧点击接口同样被拒绝。
6. 接管网站弹出的商品页，返回原结果页后关键词、排序和页面内状态保留。
7. 同标签进入商品后，通过核验过的浏览历史返回。
8. 原结果页关闭时不重新打开；离线候选读取仍可用。

原 Python 控制器 2 项、购物流程 18 项、真实 MCP 客户端桥接测试也已按明确激活流程回归。无头测试用于流程和逻辑，不作为真实焦点行为的证据。
