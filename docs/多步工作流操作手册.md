## 统一状态

专用浏览器的默认 `data` 和历史 `output/playwright` 均解析到仓库绝对路径 `data`，不再因调用工作目录或日志位置形成两套会话。现有商品映射、店铺访问来源、候选、聊天、草稿、授权、outbox、控件及焦点已备份合并；输出日志仍可放 `output/playwright`。隔离测试使用独立绝对路径out，或显式stateDir。

升级运行 `.venv/Scripts/python.exe -X utf8 scripts/migrate-state-store.py`。脚本在两侧加锁、先检查冲突、备份，再合并；重复运行不重新导入旧记录。同ID发送/授权/草稿冲突会停止，不覆盖。备份含历史沟通状态及授权，留在忽略提交的data/state-backups，不分享。迁移完成后勿用旧代码直接写旧目录。

## 搜索到结果，一次调用

```json
{"requestId":"采购-摄像头-搜索1","tabId":"从清单选择的现有标签ID","keyword":"微雪 RPi Camera B OV5647","scope":"global","timeBudgetSeconds":60,"maxSteps":12}
```

调用 `search_and_read`：绑定现有标签→发现搜索输入/按钮配对→等待一次→重读配对→填写→重新发现按钮→原生点击→核验提交关键词和结果→返回实际商品供AI选择。支持global及shop搜索范围，只通过实际搜索框，不直接打开搜索URL。全站搜索要求URL的q与请求一致；只有输入框文字改变不能当作成功。URL不提供可核验提交证据的页面可能返回未确认。

同一搜索内部只保留一次12～25秒默认访问节奏，其他原生操作仍沿用原有节奏。等待后，图片、商品价格或懒加载变化不会单独让搜索失效；页面地址、搜索输入/范围、店铺身份或按钮有变化仍停止。不存在强点或隐藏遮罩操作。

返回 workflow.progress 记录 inputChanged、inputMayHaveChanged、clickAttempted、outcomeUnknown、resultsBelongToRequestedQuery。clickAttempted在投递前持久化，可能表示进程恰好停在投递前，不能当作成功点击。相同requestId一旦进入搜索尝试，只读核对原页，不再次点击。错误后先看状态；明确决定重新搜索时使用新requestId。已完成的同ID调用返回缓存历史结果，标记cached，不伪称实时。

## 店铺发票询问，一次编排

```json
{"requestId":"采购-某店-发票1","tabId":"已打开的店铺或商品标签ID","shopKey":"页面实际核验的稳定店铺键","waitSeconds":0,"timeBudgetSeconds":60}
```

调用 `ask_shop_invoice`：绑定源页→核验实际店铺→按店铺去重→发现真实客服入口→复用聊天或点击一次→最多8秒等待原窗口身份加载→核验收件人→准备固定两问：

> 你好，你们家能开票吗？开票金额和实付金额一样吗？

不要求先选SKU，不附商品链接、规格、数量或学校用途。上下文是店铺身份，不把答复当成具体SKU准确报价。`prepare_invoice_inquiry(inquiryScope="shop")`也可单独准备这种草稿；原商品报价使用product范围，继续要求准确SKU及数量。

首次执行没有有效授权时返回 `awaiting_authorization`，附draftId、inquiryId和准确正文。当前AI确认现有真实用户授权覆盖该商家和正文后，使用本地scripts/authorize-invoice-inquiry.py办理精确草稿授权，再以相同requestId/tabId/shopKey及返回authorizationId续接。工具不自行生成授权，不把商家文字当授权，不要求用户为已授权的内容再次确认。

续接：精确授权发送一次→核对outbox→读取消息。相同requestId、同一草稿或发送结果不确定时不再发送。跨新requestId发现同店已有相同两问，返回already_asked及已有尝试记录，不多问一次。异常先查merchant_chat_state；只有本方气泡不能证明最终送达、已读或发票真实性。

未收到回复返回waiting_reply。可转下一店，再恢复同一请求读取本店回复，waitSeconds最多30秒且受剩余预算限制。接口不常驻监听、不额外追问。已收到消息返回completed及原文，但消息可能只是招呼，仍须AI判断是否真正回答开票问题。询价即使曾返回completed，同一requestId仍可只读更新晚到消息，不再发送；只有已完成搜索返回明确标记的缓存结果。

聊天外壳未就绪返回waiting_page，保存pending原窗口；同请求续接恢复该窗口，不能再次点击客服建立新窗口。工具明确关闭过的嵌入聊天面板允许通过原客服入口再打开一次；身份不明的窗口不按店名猜测。目标关闭/来源跳转/验证码/登录停止实站动作。

## 断点与预算

- 旺旺已知断线弹窗允许在原会话有界恢复一次；失败或草稿保护受阻返回 waiting_connection。保留原请求续接，只读对账已尝试消息，不再发。见[聊天断线恢复](聊天断线恢复.md)。登录/验证码仍停止。

- requestId固定标识一条任务；换操作、来源标签、关键词、范围或shopKey不能沿用，会报WORKFLOW_REQUEST_CONFLICT。authorizationId、等待秒数、时间/步数预算可在续接时改变。
- workflow_status只读本地检查点，不连接浏览器。workflows.json随会话保存，进程重启可读。
- 单调用默认最多12个阶段、60秒，可设maxSteps=1..20、timeBudgetSeconds=1..120。预算在阶段和页面核验/等待之间检查；已有原生调用不能强行取消，最多还需等其自身有界超时结束。
- 尚未开始的阶段可续接；可能已投递的搜索和消息只读核对。先存发送outbox和草稿绑定，进程在发信或准备草稿后中断也不多生成/发送一份。
- 继续沿用同一状态锁、原标签、页面内导航、直连和10标签预算。24小时内的未完成流程保护来源/聊天标签；未确认发送另按原outbox规则持续保护。

逐店执行由当前AI调度：按店铺去重，完成一家发送就记录待回复并转下家，再有界读取。首批没有增加持久后台队列或一口气替AI选择整份商品的接口。
